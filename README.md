
 Шаг 1: Подготовка структуры и секретов

Создайте файл с паролем для Redis (в соответствии с конфигурацией Docker Secrets) и структуру папок, если они ещё не созданы:
bash
# Создаем директорию для секретов
mkdir -p secrets

# Генерируем надежный пароль и сохраняем его в файл без лишних переносов строк
echo -n "SuperSecretGalacticPassword2026" > secrets/redis_password.txt

# Убедимся, что конфигурационный файл Nginx находится в правильном месте
mkdir -p nginx


Шаг 2: Сборка и запуск окружения

Запустите команду сборки всех локальных контекстов (frontend, menu-service, order-service) и старта контейнеров в фоновом режиме:
bash
docker compose up --build -d
Используйте код с осторожностью.

🔍 Шаг 3: Проверка статуса (Self-Check)

1. Проверка статуса здоровья всех контейнеров:bash
docker compose ps
Используйте код с осторожностью.
Все сервисы (включая по 2 реплики для бэкендов) должны иметь статус Up (healthy).
2. Проверка логов (убедиться, что реплики делят трафик):bash
docker compose logs -f menu-service order-service
Используйте код с осторожностью.
3. Проверка подключения к Redis:bash
docker compose exec redis sh -c "redis-cli -a \$(cat /run/secrets/redis_password) ping"
Используйте код с осторожностью.
Ответ должен быть: PONG.

🛸 Шаг 4: Проверка работы приложения

• Откройте браузер и перейдите по адресу: http://localhost (или IP-адрес вашего Docker-хоста).
• Перейдите в раздел Menu — список пицц должен успешно загрузиться (запрос пойдет через Nginx -> menu-service -> Redis).
• Сделайте тестовый заказ и проверьте его статус в Track order.
• Для проверки сохранности данных перезапустите окружение (docker compose restart). История заказов в разделе Track Order должна успешно отображаться за счет постоянного тома redis_data.
Если какой-то из сервисов долго висит в статусе starting или падает в unhealthy, пришлите:
• Логи этого конкретного сервиса с помощью команды docker compose logs [имя_сервиса]
